# Moving the site to client build 1.60.1.70374 (2026-10-14)

## Why

`GetBuildInfo()` on the beta client reads 1.60.1 70374 (12 Oct) and wago.tools lists
1.60.1.70374 as the newest `wow_classic_beta` build. The data bot had not landed it, and
the v2 release lands on main in one push, so the move is made here with the rest of the
integration instead of by a later bot commit. A diff of the raw tables against 1.60.1.70338
was cosmetic: 50 of 52 tables are byte-identical (every Item, Spell, Trait and Talent
table); `SpellItemEnchantment` only renames a column (`Condition_ID`) and
`ManifestInterfaceData` moves some icon rows. The pipeline diff is zero for spells,
talents, classes, races, sets, zones and dungeons. Three items are added (Well-Worn
Pitchfork, Crown of Maldazzar, High Priestess's Kilt: all wowhead-sourced, none in the
client's ItemSparse) and four change (Engineering Gloves, Triune Amulet, Papal Fez and
Baron Charr's Sceptre lose their `client_unconfirmed` flag; the Sceptre is item level 60,
required level 55, where it was 59 and 54). Every engine-facing output (spellconst,
levels.json, spellranks.json, talents, trainables, gametables) is identical to 70338 apart
from the build stamp, so this is a stamp move, the 70338 procedure minus any conformance
work. wago.tools also lists a never-landed 70334 between 70291 and 70338; it is skipped.

## What moved

- `data/builds/1.60.1.70374/`, fetched with the pipeline in `data.yml`'s fetch-job order
  (`fetch --product wow_classic_beta --build 1.60.1.70374`, `fetch-wowhead(-talents)`, the
  fill-in caches and hotfix dump seeded from 70338, `normalize`, `simconst`, `levels`,
  `icons`, `tree-art`, `normalize`, `weights`, `addon-data`, `loot`, `gametables`,
  `simdb`, `diff`) plus `trainables` (577 abilities) and the nightly's offline `loot-merge`.
  `loot.json` comes out identical to 70338's apart from the stamp and the rare-spawn
  flags below.
- `raw/classicdb/sources.json` is the committed 70291 one, not 70338's: the data lane's
  `npc_ranks` and `rare_spawns` keys (98c9cd2c) exist only there, and `loot` copies them
  onto loot.json as the 195 `rare_spawn` flags the ranker's rare-spawn rule reads. Seeding
  it from 70338 produced a build with no flags (the ranker logged "0 rare-spawn drop(s)
  given way") and was redone.
- `bis/` for 70374 is ranked locally with the merged ranker, because the nightly cannot run
  before the push: `make bis`, 28 specs attempted, 0 failed, 2,959 s of ranker time (46 min
  wall). `dps-per-point.json` and `addon-builds.json` (measured by the sim from the guide
  builds, no build stamp inside) are carried forward byte for byte from 70291; the
  re-measure the data README's known gaps schedules for task L9.1 replaces them.
- `web/src/data/active-build.json` and the `--check` gates in `data.yml` and
  `addon-release.yml`. History comments about the earlier fetches stay.
- All 43 guide `build:` and `raidBuild:` codes re-stamped with
  `reencode-guide-builds.mjs`: 43 stamp-only, 0 id-remaps; the survival guide's source
  links follow.
- Test pins in data, web, e2e and api moved where they mean "the active build". Kept on
  70291 on purpose: `web/src/lib/bis/source-build.test.ts` and
  `sim/leveling/bisdir_test.go` (synthetic "newer build" fixtures), the api tests that pin
  picks and marks of the 70291 files (`sims`, `rating`, `dataaddon`), the 70291
  school-enchant test name, pipeline comments, and `test_gametables_build` (69893).
- `addon/ForeverSixty/Data.lua` rendered for the build with the re-ranked bis tables (the
  documented exception to "nightly owns generated data").
- `sim/internal/spellranks/spellranks.json` is an ignored embed copied by `make simdb`;
  refreshed, nothing to commit.
- 9 of the 28 ladder goldens regenerated, all at level 30: the ladder reads the active
  build's ranked BiS weapons, and the merged ranker's 70374 tables pick other weapons than
  main's nightly (old ranker) did. The build's own item changes reach no ladder pick. No
  spell data changed.

## Windows hazard

The move was run on Windows. `pipeline fetch` writes the wago CSVs in text mode, which
turns every embedded `\r\n` into `\r\r\n`; that showed up as `\r\r\n` in `sets.json` and
`items/*.json`. The raw CSVs were converted back to the LF line endings the CI fetch writes
before the final `normalize`, after which `sets.json` was identical to 70338's. A real fix
would write the response bytes in `pipeline/wago.py`; it is not made here.

## Engine

Not part of this commit series. The 70338 move refreshed the stamp on the fork
(spellconst and relic modifiers, game tables, levels payload, base stats, the conformance
client copies and trainables, goldens). The fork was only read here (the loot step at the
pinned a73988d91), so the same stamp-only refresh for 70374 is still owed on the fork; it
moves no value, as every input is identical to 70338's apart from the stamp. The site's pin
stays at a73988d91 because no constant changed; it moves with the next real engine change.

## What the first nightly replaces

Nothing it needs to: `bis/` for 70374 is committed and ranked by the merged ranker. The
nightly's quest-level and item-source fill-ins keep running against this directory, and
its ranker run replaces `bis/` with the same code's output.
