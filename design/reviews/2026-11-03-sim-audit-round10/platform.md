| P1 | **Brotli for sim.wasm (ruling 4): done, through the Worker.** The site is Cloudflare Workers static assets, not Pages. Static assets publish no precompressed variants and document no way to label a file's own encoding (`developers.cloudflare.com/workers/static-assets/headers/`, read 2026-11-02; `_headers` overrides headers but says nothing about Content-Encoding), and `DecompressionStream('brotli')` is not in Chrome (MDN browser-compat-data: chrome `version_added: false`, crbug 463397980; Firefox 147, Safari 18.4). So a plain `.br` file is not clean. What is clean and documented: a Worker response with `Content-Encoding: br` and `encodeBody: 'manual'` sends stored bytes as they are (`developers.cloudflare.com/workers/runtime-apis/response/`: "Set this to `"manual"` when serving pre-compressed data"). Now: `make publish-wasm` writes `sim.wasm.br` (brotli -q 11 -w 24) beside `sim.wasm.gz`; `wrangler.jsonc` routes only `/_sim/*/sim.wasm.gz` to the Worker; `web/src/lib/sim/wasm-serve.ts` sends a browser that accepts br (read from `request.cf.clientAcceptEncoding`, Cloudflare rewrites the header) the `.br` bytes under the `.gz` URL with `Content-Encoding: br`, `application/wasm`, `Vary: Accept-Encoding`, immutable cache; anything else, or a missing `.br`, gets the gzip exactly as before. The browser decodes natively, so `wasm-fetch.ts` receives the module (its existing wasm-magic branch) and `instantiateStreaming` is unchanged. `astro preview` and every Playwright run have no Worker and keep the gzip path the real-engine CI job proves. ## For other lanes

- **Integrator, at merge:** after merging any lane that changes a guide's rotation prose, a preset food or potion, or the active build, run `python tools/coach/persona_starter.py --all` from the repo root and commit the starters; `coach.yml` now fails when a starter lags its inputs. The ranks lane's Retribution guide and the auras lane's potions both qualify.
- **Integrator, first deploy:** check `content-encoding: br` on `/_sim/<artifact>/sim.wasm.gz` with a Chrome Accept-Encoding (P1). If the edge ever answers gzip there, the page still works; the saving is just lost.
- **Ranks lane:** `sim/request/rank_choices_lookup.go` is a new read-only accessor over your embedded table for the coach; it does not touch the rewrite. If the table's shape changes, its test will say so.
- **Data (whoever regenerates at the hold's end):** the first full data run writes the panel's 98 new ids and 29 corrected icons into `simbuffs.json` and fetches 98 icons (one from wowhead). `icons` runs before `loot` on a full night, so an id new that night gets its art the night after.
