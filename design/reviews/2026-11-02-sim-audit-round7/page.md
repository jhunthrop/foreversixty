| P5 | **Crit rates on a browser run's Damage tab were wrong.** /sim splits a run across workers, and `sim/combine` merges the parts. Each part's row counters were weighed by its iteration share and rounded before the parts were added. Any count a part saw less than about twice a fight disappeared, and others were pushed up. With 8 parts, Ignite's 3 crits a fight became 3/8, which rounds to 0 eight times, so the tab read 0.0%. Scorch's 12 crits of 46 hits became 16 of 48 (33.3% instead of 26%). Shoot read 0.0% instead of 6.9%. A level-30 Affliction warlock's Shadow Bolt, Corruption, Agony and Immolate all read 0.0%. Totals (and DPS) were barely touched, because they are large numbers. **Fix:** a merged row sums the weighed values and rounds once (`rowSums`). The per-part `mergeMisses` is deleted as dead code. The same code combines server runs (`sim/cmd/forever-sim`). | `combine_test.go` `TestResultsRoundsEachRowOnceNotOncePerPart` failed first with exactly the page's figures ("hits 48 crits 16 … crits 0 ticks 24"). Any client id reaches the shards automatically. sim.yml does not run on a BiS-only push, so the nightly cannot turn it red, but a pin bump that adds an engine-only id will.
