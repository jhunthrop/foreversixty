# Moving the site to client build 1.60.1.70338 (2026-10-13)

## Why

wago.tools listed 1.60.1.70338 as the newest `wow_classic_beta` build and the
data bot landed `data/builds/1.60.1.70338/` (23c8df38). The diff against
1.60.1.70291 is cosmetic: 31 items added, 63 items changed (mostly quality),
one spell added (Summon Azurky), nothing else. Every engine-facing output
(talents, spellconst, gametables, levels.json, spellranks.json) is
byte-identical to 70291 apart from the build stamp, so this is a stamp move:
the 70291 procedure minus any conformance work.

## What moved

- `pipeline trainables --build 1.60.1.70338` (577 abilities). The raw tables
  are ignored, so they were fetched into the worktree first. All nine class
  files are identical to 70291's apart from the build stamp.
- `active-build.json` and the `--check` gates in `data.yml` and
  `addon-release.yml`. History comments about the 70291 fetches stay.
- All 43 guide `build:` and `raidBuild:` codes re-stamped. The script reported
  43 stamp-only, 0 id-remaps; the survival guide's source links follow.
- Test pins in data, web, e2e and api moved where they mean "the active
  build". Kept on 70291 on purpose: `source-build.test.ts` and
  `sim/leveling/bisdir_test.go` (synthetic "newer build" fixtures), the
  70291 school-enchant test name, pipeline comments, and
  `test_gametables_build` (69893).
- `addon/ForeverSixty/Data.lua` rendered for the build (the documented
  exception to "nightly owns generated data"); its bis tables are empty
  until the nightly. `stat-weights.json` and `addon-data.json` for the build
  were already identical.
- `sim/internal/spellranks/spellranks.json` is an ignored embed copied by
  `make simdb`; refreshed, nothing to commit.
- 17 ladder goldens regenerated: the changed item qualities move some level
  30 and 38 weapon picks and a few percent shares. No spell data changed.

## Engine

Stamp-only refresh on the fork, pin unchanged at a73988d91 because no
constant changed.

## What the first nightly replaces

`bis/` for 70338 (until then the web loader serves the newest other build's
ranked files, each stamped with its own build), and it re-renders
`addon/ForeverSixty/Data.lua` with the bis tables filled in.
