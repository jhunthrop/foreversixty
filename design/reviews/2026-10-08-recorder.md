# Measurement recorder (lane `recorder`, 2026-10-08)

Branch `recorder`, from main c1c5bccc. Not merged, not pushed.

## What it is

`/fs record on|off|status|clear` records, while on, the events the simulator cannot read from
the client tables, into `ForeverSixtyDB.recorder` (schema 1, ring buffer of 20,000 events,
snapshots of the last 20 sessions). `python -m pipeline recorder <ForeverSixty.lua>` fits them.

| Item | Addon (what is stored) | Pipeline (what is reported) |
|---|---|---|
| Energy | every changed ENERGY value, time, max (UNIT_POWER_UPDATE/FREQUENT) | commonest uncapped gain and median tick interval, with counts |
| White swings | player SWING_DAMAGE/MISSED: hand, outcome, damage, target level and type; pet swings counted only | outcome rates by hand and level gap with Wilson 95%, mean glancing damage / plain hit damage |
| Yellow | Eviscerate, Sinister Strike, Backstab, Mutilate: outcome, damage, combo points spent, attack power, target | Eviscerate `base + points*per_point + ap*points*ap_term`, least squares with standard errors |
| Windfury | SPELL_EXTRA_ATTACKS and SPELL_AURA_APPLIED on player and pet, with the preceding swing or special within 100 ms | procs by unit and preceding kind, proc rate over counted swings/specials, auras by unit |
| Mana | every changed MANA value with seconds since the last cast; spirit, intellect, mp5 at session start | per-tick gain inside and outside the five-second rule, fit a + b*spirit across sessions |
| Shadowfiend | SPELL_ENERGIZE to the player from Shadowfiend / Dark Sacrifice | returns, mean amount, median gap |

## Decisions worth a second look

- Off means off: no frame, no registered event until the first `on`; `off` unregisters all.
  No chat output while recording; the slash command answers a line. Not persisted across
  `/reload`: a recorder left on by accident cannot outlive the session.
- One clock: every event uses `GetTime()`, not the combat log's wall-clock stamp, so power
  events (which carry none) and combat events can be ordered and the 100 ms window applied.
- Combo points spent: the value before a drop within 0.5 s of the cast, else the current
  value, because the order of UNIT_COMBO_POINTS and the damage log line is not guaranteed.
  Only meaningful for finishers; generators record the same field.
- Windfury ordering is unknown: if the log writes the proc before its swing, the next action
  of that unit within 100 ms completes the record and marks it `after`; the report counts
  those separately and gives them no rate.
- Rate denominators are per-session counters of every player and pet swing and special
  (`counts`), which cover the whole session while the ring buffer may have dropped the
  oldest events. Fits use events only; rates use counters.
- Spell names are matched in English; `Recorder.YELLOW_SPELLS` and the fragments next to
  it are the single place to change.
- Unconfirmed against the real client (the spike checklist style applies): that
  `UNIT_COMBO_POINTS`, `UnitAttackBothHands`, `GetManaRegen` and `GetComboPoints` exist on
  1.60 (each is called through `try`, so a missing one leaves a nil field rather than an
  error); the Shadowfiend's real spell names; mp5 is `GetManaRegen()`'s casting rate * 5.
- The pipeline reader is new: there was no Python SavedVariables reader. `savedvars.py` reads
  the Lua subset a SavedVariables file uses (tables, strings, numbers, booleans, comments).
- Eviscerate damage is post-mitigation; the fit's standard error is the guard. Fight one
  armor class of target and vary attack power.

## Verification

- `busted`: 745 pass (716 before, 29 new in `addon/tests/recorder_spec.lua`, plus the TOC
  order test updated). `luacheck ForeverSixty tests`: 0 warnings. Both run on Lua 5.5 here; CI
  runs 5.4 and a 5.1 syntax check, and the new code uses only 5.1 constructs.
- `uv run pytest tests -q --no-cov -k recorder`: 44 pass; `uv run ruff check`: clean.
  Recorder modules are at 99-100% line coverage.
- Smoke: the Lua recorder driven with fake client calls, serialised the way SavedVariables
  is, and read by `python -m pipeline recorder`: energy 20 per 2.000 s, a glancing swing and a
  Windfury proc came out as expected.
- Not done: a real-client run. That is the point of the tool.
