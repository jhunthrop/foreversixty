## The fix

- **The deployed module is gzipped.** `make publish-wasm` writes `sim.wasm.gz` (`gzip -9 -n`, 4,464,151 bytes at the pin) beside sim.js instead of the raw module. The directory id still hashes the raw sim.wasm. The page fetches `sim.wasm.gz` and passes it through `wasmResponse` (web/src/lib/sim/wasm-fetch.ts). That function inflates it with `DecompressionStream('gzip')` and hands an `application/wasm` response to `instantiateStreaming`, so compiling still overlaps the download. It sniffs the magic bytes and passes an already-inflated module through, for a host that labels the file `Content-Encoding: gzip`. astro preview does that (checked with curl: `Content-Type: application/wasm`, `Content-Encoding: gzip`), so the local and e2e builds take the passthrough path. Cloudflare static assets are expected to serve a `.gz` as stored (application/gzip, no Content-Encoding), which means the inflate path. That is not verified until the first deploy. Either way the page works, and both paths have unit tests. A failed or foreign body throws with the URL. The visitor's download is the same size as before, because the edge already compressed the raw file (4.47 MB gzip and 4.27 MB br before, 4.46 MB now). The stored file drops from 24.8 MB to 4.5 MB, so the per-file limit is now about 5.9x away instead of 1.06x. This is the smallest change: it needs no worker route, no R2 token (the DuckDB R2 upload still waits on one) and no new build tool. The file name is `version.ts`'s `WASM_FILE`. engine.ts, check-sim-engine-artifact.mjs, web.yml's artifact check and the real-engine e2e probe all read it. sim-gear-real-engine.spec.ts's duplicated probe now calls the shared support/real-engine.ts.
- **A per-file budget below the limit.** web/scripts/asset-budget.mjs holds `CLOUDFLARE_ASSET_LIMIT_BYTES` (25 MiB) and `ASSET_BUDGET_BYTES` (20 MiB) as configuration, plus `measureAssets()`. check-island-size.mjs, which runs in `npm run postbuild` on every build including the deploy's, now fails any dist/ file over the budget, not just over the limit. Tests: src/lib/build/asset-budget.test.ts. Dry run: `measureAssets` on a directory holding the raw pin sim.wasm (24,828,918 bytes, under 25 MiB) reports it over the 20 MiB budget and exits 1. The same directory with only the published sim.wasm.gz passes.
- **The Makefile builds with CI's toolchain.** `GO_TOOLCHAIN := go$(sed 's/^go //' sim/go.mod)`, and `GOTOOLCHAIN=$(GO_TOOLCHAIN)` is set on both builds and on the `go env GOROOT` that sim.js is copied from. A laptop now builds the 24.8 MB module CI builds; go downloads 1.25.11 once if needed. It is a no-op on CI.
- **A warning when the engine is not the pin.** tools/engine/check-checkout.sh runs first in `make artifacts`. When the engine resolves to a local directory whose HEAD is not the pin, or is the pin but dirty, it says so on stderr and gives the worktree plus GOWORK recipe from memory forever-sim-goldens-locally.md. It never fails, so the developer flow of building the fork checkout still works. It says nothing on CI (a module path, not a directory). Tests are in tools/engine/tests/test_scripts.sh.
