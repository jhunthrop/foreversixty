# 2026-10-07 bulk-store test failures after the nightly loot regeneration

## Finding

None of the five failures is a store defect or a stale expectation, and the nightly data is not
wrong. `src/lib/sim/bulk-store.test.ts` reads its loot, simitems and class files through
`src/test-support/sim-api.ts`, which serves them from `web/public/data/<active build>/`. The
`npm test` script runs `pretest` (`FOREVER_DATA=fixture npm run sync`), so that directory holds
`src/fixtures/planner` and the assertions (Lucifron's Helm of Wrath, Ragnaros 11502 with two
drops, fixture-only ids such as 90011, Azuregos with an unknown date, 21550 missing from
simitems) hold. `npx vitest run <file>` skips `pretest`. The main checkout's `public/data` was
last written by `precheck` / `predev` / `prebuild` (`npm run sync`, real mode), so the test read
the real 1.60.1.70009 loot.json (3172 sources, Onyxia's Lair drops Helm of Wrath, Molten Core
is `later`, Azuregos has a date, 21550 is in simitems).

Evidence: in a fresh worktree, `FOREVER_DATA=fixture npm run sync` then the file gives 48/48;
the whole `npm test` gives 3229 passed, `npm run check` 0 errors, `format:check` clean.

## Decisions per failure

1. Helm of Wrath source index: test correct for the fixture; real data (Onyxia) is also right.
   No change.
2. Open sources without Molten Core: fixture-only assumption; real `raid:molten-core` is
   `opens: later`, which the gating rule rightly hides. No change.
3. Fourteen identical `drop:raid:molten-core:11502`: not de-duplication. With real data the
   boss lists many items that survive the simitems filter; the store emits one candidate per
   item by design. The fixture lists two. No change.
4. `world:azuregos` visible by default: real data gives it a date, so the contract 10.4
   gating (hide unknown date until show-upcoming) correctly does not apply. No change.
5. `addSearchItem(21550)` false: 21550 is in the real simitems and not in the fixture's, so
   the "unknown to the engine" path is not reached. No change.

## Data defects for the pipeline owner

None proven. Observation only: nothing in the repo stops a real-mode sync from leaving
`public/data` in a state where a direct `npx vitest run` fails confusingly. Running scoped
tests needs `FOREVER_DATA=fixture npm run sync` first (or use `npm test -- <file>`, which runs
`pretest`). Making `sim-api.ts` read `src/fixtures/planner` directly would remove the
dependency; that file is outside this lane's remit.
