# Logs page redesign: experience spec

Author: ux-designer. 2026-10-11. Revises `design/specs/2026-10-04-logs-landing.md` (sections 4.A, 4.B and the grid order); sections 4.C (guild tab, sample de-duplication), 4.D.1 and 4.D.2 (device status, pairing confirmation) and the data defect on the sample report stay. Route `/logs` (`web/src/pages/logs.astro`, `LogsHeroBand.svelte`, `LogsHero.svelte`, `MyReports`, `RecentReports`, `Upload`, `CompanionStatus`, `Account mode="pairing"`). Mock: `design/mocks/gen_logs.py` (revised); renders `design/mocks/renders/logs{,-signed-out,-2000,-1024,-phone,-states}.png`. Header: `2026-10-11-character-header.md`.

## 1. The one job

**"Upload a log, or open one, and read it."** Signed in the page leads with the shared header: `Latest kill: 612 DPS, Onyxia kill, 3 days ago`, then `Last report 1 day ago` when a report is newer than the kill (or `No logs yet`), action `Upload a log` (on a phone `Open your latest report →`). Recent reports and the upload drop zone follow.

## 2. Decisions

1. **The report-as-hero goes.** The old band led with the visitor's newest report (or the sample, with a `Sample` pill), its facts, `Open this report`, and a hook (`Last kill, ...: {Name} · DPS · Gear in the planner | Sim`). The shared header now carries the character's latest parse; the report list is directly below; the gear and sim hand-offs live on the report page itself (`planner-link.ts`, `sim-link.ts`) and leave the landing. The `Sample` pill is gone (no pills; the sample is a plain row labelled `A sample report` in Recent public reports and, signed out, a gold text link in the band).
2. **Band.** Eyebrow `Combat logs`, h1 `Logs`, job line `Upload a combat log or log live, then read every pull.` No stamp (a list page has no build date). Signed out, one more line: `See what a report gives you: Open the sample report →`.
3. **Header.** Answer: label `Latest kill`, figure `{value} {DPS|HPS}` (one decimal under 1,000, whole with a thousands separator at or above), note `{Encounter} kill · {age} · Open the fight →` (gold inline link to `/reports/{id}?fight={n}`, the arrow never wraps), and a second note `Last report {age}`, **a link to that report** (underlined, muted), shown only when the newest report is newer than the newest kill, so a wipe night reads as a report, not a stale header. Percentile, when the API sends it, replaces nothing: it is not shown here (Rankings owns it). Empty: `No logs yet. Upload one, or log live with the companion.` Source: the character's `history[0]` from `GET /v1/characters/{region}/{ruleset}/{name}` (`CharacterFight`: encounter, metric, value, fought_at, report_id, fight_index). This is the character's **latest ranked kill**, not any fight; round 2 settled the wording as `kill` plus the report line. Ages use one rule everywhere: relative inside two weeks (`3 days ago`), else a date (`Sep 15`).
4. **Action.** `Upload a log` (48 px filled gold, the page's only one) opens the system file picker from the click. **The outline `Upload` button appears only after a file is chosen** (round 2), together with Title and visibility; before that the panel is the explanation and the zone (`Drop WoWCombatLog.txt here, or choose a file`). Cancel returns focus to the zone. On a phone the header action is `Open your latest report →` and Upload lives only in the upload panel. Signed out the header is the shared band and every panel says in plain words that it needs a signed-in account; the page has no sign-in buttons.
5. **Layout, two columns by verb (1440, 7/5).** Left, **open and read**: `Your reports` (guild tabs kept; each row is the title and a relative date, with `{Zone} · {n} bosses · {length}` under it, e.g. `Blackrock Depths · 4 bosses · 2 h 10 m`), then `Recent public reports` (the sample is a plain row of its own, `Sanguine Depths, sample log`, `12 kills`, `Sep 15`, never the same row as yours). Right, **ways in**: `The companion` above `Upload a log` when a device is paired, below it when none is (round 2: the live logger's route first); the zone is 150 px tall. The framing sentence (`Logs are for group content at any level...`) is cut from the page (the job line and the empty states carry it); the dungeon point stays in `Recent public reports`' empty line. The `CurrentCharacterBar` spine is removed.
6. **Phone (390).** Reading is the phone job (a raid leader checks last night on a phone; logs are uploaded from a PC). Order: header (`Open your latest report →`), `Your reports`, `Recent public reports`, then the two ways in in the same paired or unpaired order as desktop. 1024 and below 1100: one column, left stack then right stack. 2000: the 1344 column, the band full-bleed.
7. **Signed out.** No header. The shared band replaces the header; the sample report appears once, as the row in Recent public reports (the band's intro link is gone). The same two columns with plain sentences (`Reports you own appear here once you are signed in.`, `Uploading needs a signed-in account; the report is filed under it.`, `Pairing needs a signed-in account.`) and no buttons; this supersedes the 2026-10-04 amendment that made every sign-in action an outline button, since pages now carry none. Nothing is hidden behind sign-in that a visitor could read (the sample and any public report).

## 3. States

`logs-states.png` and the header sheet: header ready and empty (and every shared state); `Your reports` list, empty (`No reports yet. Upload a log, or log live with the companion.`), loading, signed out; upload with a file chosen, signed out, dragging over (gold edge, 6% tint, nothing moves), failed (`The upload did not finish. Your file is untouched; try again.`, generic, the technical detail stays in the console); recent public reports; companion paired. Hover on a report row underlines the title and moves nothing; every target 44 px or more; the drop zone is a labelled group with a real `<input type=file>` behind it for keyboard and touch.

## 4. Copy

Eyebrow `Combat logs`; h1 `Logs`; job line above; header label `Latest kill`; action `Upload a log`; panels `Your reports`, `Recent public reports`, `Upload a log` (aside `For a night already logged`), `The companion` (aside `Live, while you raid`); upload body and folder note as shipped, with `stop logging first, so the file is whole`. Sample label `A sample report`.

## 5. Data and notes for the lane

No new endpoint for the header (the character page read already exists and is public). Reuse `fetchMeOnce`, `listMyReports`, the report-row component. Delete from the page: `LogsHeroBand`, `LogsHero`, `hero-hook.ts`'s landing use, `logsFraming`, the sample `Sample` pill and its test ids. The sample report's Monk row (2026-10-04 section 4.C.3) is still a blocking data defect for the public sample; this mock reads only the report's counts (63 fights, 12 kills) and encounter name. The character, other report titles, device and pairing code in the mock are invented; the reports numbers are the real sample's.

## 6. Acceptance

1440 signed in and out, 2000, 1024, 390; the header resolving with no shift; the picker opening from the button; each state above; side by side with the 2026-10-04 board (`logs-signed-in.html`). Tests: header present signed in only, `Upload a log` opens the picker, no pill class, one filled gold element, no spine, reports order on phone.

## 7. Open questions

1. `Latest kill` is the latest ranked kill; does the owner want wipes (needs a report-level read, not the character page)?
2. Is `The companion` better above `Upload` for players who log live?
3. Dropping the framing sentence: the dungeon-logs point now lives only in an empty state.

## 8. Round 2 (WoW player round-one review, decisions applied)

Wording `kill` plus the newer-report line; phone action `Open your latest report →` with Upload only in the panel; companion above Upload when paired; outline Upload only after a file is chosen; relative dates; zone, boss count and length on rows; the 1024 arrow is non-breaking and the identity column widens below 1280; the sample row is a different report from the own rows; no page sign-in controls. Not done: wipe-level detail in the header (a wipe needs a report-level read; open question 1); a paired device shows its status row and the pairing code stays in the panel for adding another device.

## 9. Round 3

`Last report 1 day ago` links to that report; the signed-out panel order is Upload then Companion, the same as signed in without a device; the sample appears once; the Onyxia kill is 3 days ago here and on Rankings. Changed captures: `logs*.png`.
