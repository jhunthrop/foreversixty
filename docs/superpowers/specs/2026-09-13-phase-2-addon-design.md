# Forever Sixty — Phase 2 design (addon, stat weights, gear tail)

Date: 2026-09-13. Status: approved in conversation. Window: Oct 10 to Nov 4, 2026, with the
Sept 17 beta spike and the addon data generator started as soon as Phase 1 merges.

## Goal

Ship the ForeverSixty in-game addon so that a shared build becomes an in-game leveling guide and
a character's real talents and gear flow into the planner with one paste. Finish the gear picker
so its numbers are honest. Everything the addon needs is generated by the data pipeline and
carried in strings the player copies, because addons cannot use the network.

## Scope

### In

1. **Beta spike (Sept 17).** Confirm the beta client loads addons, the interface version number,
   and the exact API calls for talents (`GetNumTalentTabs`, `GetNumTalents`, `GetTalentInfo`),
   equipped items (`GetInventoryItemLink`), bag items (`C_Container.GetContainerItemLink` or the
   Classic equivalent), and item stats (`GetItemStats`). Record the findings in `addon/README.md`.
   If addons do not load in the beta, develop against Classic Era and verify at launch.
2. **Addon data generator** in the pipeline: `addon/ForeverSixty/Data.lua` per release, with per
   class the tree layout as tab position, tier, column, talent name and max rank; the stat weights
   per spec; and the data build id.
3. **Export string** (addon to site) and **addon code** (site to addon) formats, with encoders and
   decoders in Lua and TypeScript that share fixture vectors.
4. **Follow**: next-point frame and talent-window highlight driven by a loaded addon code.
5. **Gear upgrades**: in-game panel scoring equipped and bagged items against the planned gear.
6. **Site**: `/addon` page; import box on the planner; "Addon code" button in the share panel;
   score column and sort in the gear picker; stat-weight display.
7. **Stat weights**: `data/curated/stat-weights.json`, sourced, per class and spec, emitted into
   the build directory and into `Data.lua`.
8. **Gear-release tail**: weapon damage and speed; a `two_hand` flag with the matching validation
   rule; secondary stats from equip effects; effect-only items with effect text.
9. **Packaging and publishing**: the BigWigs packager in a GitHub Actions release workflow
   publishing to GitHub Releases, CurseForge, and Wago Addons; luacheck and busted in CI.

### Out

Companion app, combat logs, accounts (Phase 3). Realm picker, queue tracker, leveling routes.
Simulation, in-game DPS meters, raid-frame features. Retail or SoD clients.

## Architecture

```
data/ pipeline ──▶ data/builds/<build>/stat-weights.json, addon-data.json
               ──▶ addon/ForeverSixty/Data.lua   (generated, committed per release)

addon (Lua, in game)                          site (Astro + Svelte)
  Export.lua  ──FS1 string──▶ paste ──▶ planner import box ──▶ build draft
  Follow.lua  ◀──FSB1 code── paste ◀── share panel "Addon code" ◀── build record + item stats
  Gear.lua    scores GetItemStats(link) · weights[spec]  vs planned gear carried in the FSB1 code
```

- The addon never needs the site's item database: the addon code carries each planned item's
  stats, and equipped and bagged items are read from the client with `GetItemStats`.
- Talents are matched by tab position, tier, and column rather than by talent id, so a client
  patch that renumbers talents does not break follow; the addon code carries the same triple.
- The addon shows its data build id in its options panel and in the export string; the planner
  warns when an import comes from an older data build than the site's active one.

## Formats

**Export string** `FS1:<data-build>:<class-slug>:<race-slug>:<t1>/<t2>/<t3>:<slot>=<item-id>,...`
where `<tN>` is the ranks of that tree's talents in tab order as a base-36 digit each, unspent
trailing zeros trimmed. Example: `FS1:1.15.9.69722:paladin:human:503200000/0/0:head=12640,chest=11726`.

**Addon code** `FSB1:<data-build>:<class-slug>:<order>:<gear>` where `<order>` is one triple per
point spent, tab index, tier, column each one base-36 character, concatenated; `<gear>` is
`<slot>=<item-id>:<stat>=<value>;...` pairs separated by commas. The site emits it from the build
record and its item data; the addon decodes it without any lookup beyond `Data.lua`.

Both formats are versioned by prefix; decoders reject unknown prefixes with a message naming the
addon and site versions involved.

## Stat weights

`data/curated/stat-weights.json`: `[ { "class_slug", "spec": "holy", "weights": { "intellect": 1, ... },
"sources": [ { label, url, kind } ] } ]`. Every entry has at least one source. A build's spec is
the tree with the most points; ties resolve to the first tree. Score = Σ weight × stat; shown in
the planner's gear panel and used by the addon. Weights are opinions, labeled as such on the site
with their sources, and revised as the beta reveals Forever's changes.

Stat vocabulary (Deep Dive panel, Sept 13): Forever merges melee, ranged, and spell hit into one
`hit` stat and the three crit chances into one `crit`; adds `expertise` (reduces the target's parry
and dodge chance); bonus healing carries one third of its value as bonus damage; caster weapons
grant spell damage. Weight keys therefore use the merged names (`hit`, `crit`, `expertise`, `haste`,
`spell_power`, `healing_power`, `attack_power`, plus the five primaries and `armor`, `defense`,
`block`, `dodge`, `parry`). The gear panel's stat summary uses the same keys. Vanilla items with
per-school hit or crit map onto the merged stat until the Sept 17 beta data replaces them.

## Gear tail (data, api, web)

- `damage_min`, `damage_max`, `speed` on weapons; `dps` derived.
- `two_hand: true` on two-handed weapons; validation rule 6 gains "an off-hand item with a
  two-handed main hand is refused" in both the API and the client mirror.
- Secondary stats from `ItemEffect` → `Spell` → `SpellEffect` aura amounts, mapped to the same
  stat keys; the mapping table lives in the pipeline with a test per aura kind.
- `effect_text` for items whose value is a use or proc effect, from the spell description with
  the same token substitution as talents.

## Addon structure

```
addon/ForeverSixty/
  ForeverSixty.toc      Interface number from the spike; SavedVariables: ForeverSixtyDB
  Data.lua              generated
  Codec.lua             FS1 / FSB1 encode and decode, pure
  Talents.lua           read the talent window, map to tab/tier/column
  Export.lua            build the FS1 string, show it in a copyable edit box
  Follow.lua            next point, frame, highlight
  Gear.lua              scoring, panel
  Options.lua           slash command /fs, data build id, toggles
tests/                  busted specs for Codec, next-point, scoring with a mocked WoW API
.pkgmeta                packager config
.luacheckrc
```

## Site additions

- `/addon`: what it does, install links to CurseForge, Wago, and the latest GitHub release, the
  current data build id, and the two paste flows illustrated. Reference voice.
- Planner: an "Import from addon" box that accepts an FS1 string, builds a draft with the final
  tree and an approximated order (tiers in ascending order, left to right), and shows a note
  that the order is approximated.
- Share panel: "Copy addon code" next to the link, generating the FSB1 code client-side.
- Gear panel: weighted score per item and for the set, a sort by score, and the spec's weights
  shown with their sources.

## Error handling

- Decoders return a specific reason for every malformed input; the planner and the addon show it
  verbatim, never a generic failure.
- A code from a newer data build than the addon has is refused with the version pair.
- Missing weights for a spec: score hidden with a note, never zero.
- Packager failures fail the release workflow; nothing is published partially.

## Testing

- Lua: busted specs for Codec round-trips against shared fixture vectors, next-point selection
  including prerequisites and maxed talents, and scoring; luacheck clean.
- TypeScript: the same fixture vectors for the codec; import approximation; score math.
- Data: generator tests on the Data.lua output and the stat-weights source enforcement; the gear
  tail's aura mapping and damage fields with fixtures and golden files.
- API: the two-hand rule with passing and failing cases.
- E2E: paste an export string and see the tree; copy an addon code and decode it in the
  TypeScript decoder; gear panel score sort.
- Manual, recorded in the README: the spike checklist in the beta client; follow and gear panels
  exercised on one character per role.
