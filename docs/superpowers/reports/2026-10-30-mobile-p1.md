## 1. OpenAPI as the source of truth

**The spec.**
- `api/openapi.yaml` now covers every route and static file in `docs/contracts/app-v1.md`.
  - That includes the dark routes: A1's start, continue, exchange and logout; A2's notifications and push tokens; A3's character home and app config.
  - It also has a schema for each push payload, and new schemas for the guild raids, raid view, sign-up, loot and static files.
- The whole file is now valid OpenAPI 3.1. Its 40 `nullable: true` were turned into type arrays, because a 3.1 validator rejects `nullable`.
- `api/internal/server/openapi_test.go` now reads nullability the 3.1 way.

**Conventions the generator reads.** They are written at the head of the "Native apps v1" components block.
- Tags:
  - `app` is an API call;
  - `app-static` is a CDN file;
  - `app-browser` is a URL the app opens in the browser, and gets no generated code.
- Every object is a component or has a `title`, and that names its generated type.
- `x-name` renames a field whose JSON key is a reserved word (`class` becomes `className`, `in` becomes `signedIn`).
- `x-fixtures` lists a response's fixtures. `x-fixture-route` names the fixture that fixture mode answers.
- `x-authenticated: false` marks the calls that send no token: exchange and config.

**The test.** It lives in `api/internal/contract`: `openapi_test.go` and `undeclared.go`.
- Every fixture in `docs/contracts/fixtures/app/` must be claimed by an `x-fixtures` list.
- It is validated against its response schema with **libopenapi-validator v0.14.0**, maintained, by pb33f.
  - That is the newest release that does not need Go 1.26. Later releases would raise `api/go.mod` past the `golang:1.25` Docker image.
- The library's own strict mode in v0.14 cannot read `allOf` or `additionalProperties`. So a small walker, with its own unit test, fails on any fixture key the spec does not declare.

**Drift the test found and fixed.**
- `User.premium` was required in the spec but is never serialised.
- `SimResult.title` was missing from the spec.
- The `character.card` fixture carried test-data words outside the real enums: tier `gold`, rank `Officer`. They are now `common` and `officer`, along with the seed in `rankings/app_contract_test.go`.

**Generators: in-repo for both platforms.** `web/scripts/gen-mobile-api.mjs` plus `web/scripts/mobile-codegen/`.
- Both apps already own a small client that has the envelope, the bearer token, the 401 rule and fixture mode built in.
- swift-openapi-generator brings its own Client and transport types and runs as a build plugin.
- openapi-generator needs a JVM CLI and writes Retrofit or Ktor clients.
- Either would replace or wrap code that works. The in-repo generator writes plain types that plug into the existing clients:
  - **iOS:** Codable structs, plus `Endpoint` and `StaticResource` members such as `client.send(.getMe)` and `.getCharacter(region:ruleset:name:)`.
  - **Android:** `@Serializable` data classes, `ApiEndpoints` and `StaticEndpoints`, and `ApiClient.send(endpoint)`.
  - **Both apps:** a `ContractRoutes` table that both fixture transports now read. This closes the integration report's concern 4: two route tables that nothing compared.

**Cleanup.**
- The hand-written models are deleted from both apps.
- What they did beyond shape (`mainCharacter`, `Identifiable`) is now extensions on the generated types.
- Two names changed in the apps: `CharacterCard`/`Character` is now `AccountCharacter`, and `AppExchangeResponse` is now `AppSession`.

**Drift check.**
- `web/src/lib/mobile/api-codegen.test.ts`.
- `.github/workflows/mobile-codegen.yml` runs every mobile drift check (tokens included) on any change to a source, an output or a generator. The web workflow runs the same tests with its unit suite.

## 2. One copy catalog

**The catalog.** `apps/shared/copy/en.json`:
- holds every key in the spec's section 13;
- holds the shells' current strings under `shell.*`;
- supports placeholders, int args, plurals and per-platform words.

**The generator.** `web/scripts/gen-mobile-copy.mjs` writes:
- `apps/ios/App/Localizable.xcstrings`;
- typed accessors in `apps/ios/App/Generated/Copy.swift`, for example `Copy.talentsUnspent(n:)`;
- `apps/android/app/src/main/res/values/strings.xml`, with `<plurals>`, positional `%1$s`/`%1$d`, aapt escapes and quoted edge spaces.

**What the generator refuses:**
- placeholders that differ between platforms;
- a plural form that names a placeholder other than its count;
- a plural form that does not show its count (the String Catalog's own rule);
- two keys that share an Android name;
- the spec's banned words. "Unlock sign-ups" is allowed as the officer action.

**The shells.** Both now read their strings from the catalog. The screenshots are unchanged.

## 3. One deep-link table

**The table.** `apps/shared/links.json` holds the nine `/app/*` paths of spec section 6.4. Each has its typed parameters, its allowed query words, its screen and an example.

**The generator.** `web/scripts/gen-mobile-links.mjs` writes:
- **iOS:** a new `Routing` module with `DeepLink` (`init?(url:)`, `screen`, `url`).
- **Android:** `navigation/DeepLink`, with `parse` and `url()`. MainActivity now routes the sign-in return through it.
- **Web:** `web/app-link-paths.json`, the path patterns.

**Tests in both apps.**
- Every route's example parses and round-trips.
- Each route's parameters are checked.
- The near misses are refused: a wrong host, `http`, off `/app/`, a non-numeric id.
- An unknown query word is dropped.

**Merge point with A1.**
- A1's `web/scripts/app-links.mjs` is on `wt/mobile-auth`, not on main.
- When it merges, `readAppLinksConfig` should take `paths` from `web/app-link-paths.json` and drop `paths` from `web/app-links.json`.
- The AASA `components` and the Android filter then list the exact paths instead of `/app/*`.

## 4. Feature switches

**The contract.**
- `GET /v1/app/config` gains `features: {key: bool}`, always present and `{}` when empty. `min_app_version` and `active_build` were already there.
- The change is in the spec, `app-v1.md` and the `app.config` fixture.

**The defaults.**
- `apps/shared/features.json` holds eight keys: `sign_in`, `character_home`, `bis`, `raids`, `sims`, `talents`, `notifications`, `premium_link`. All are off.
- `gen-mobile-features.mjs` generates both apps' `Feature` enums with their bundled defaults.

**The clients.** iOS `AppConfigStore` and Android `AppConfigRepository`:
- fetch at launch (RootView and MainActivity);
- cache the last good answer (UserDefaults on iOS, a private file on Android);
- answer from the cache, else the bundled defaults, when offline;
- expose `isEnabled(feature)`, `requiresUpdate(version)` and `mayLinkToWebCheckout(storefront)`;
- ignore a key the build does not know.

**The one addition A3 needs** (`api/internal/app`, not touched here). Add one field to the config view:

```go
Features map[string]bool `json:"features"`
```

- Fill it from config, for example `APP_FEATURES=raids,sign_in` → `{"raids":true,"sign_in":true}`.
- Send it as `{}` when the variable is unset.

## Interfaces for other lanes

**Changing an API shape.** Edit `api/openapi.yaml` and the fixture together, then run `node web/scripts/gen-mobile-api.mjs` and commit. Do not hand-edit anything under `Generated/`, `ApiModels.kt`, `ApiEndpoints.kt` or `Feature.kt`.

**Making calls.**
- iOS: `client.send(.<operationId>(...))`.
- Android: `client.send(ApiEndpoints.<operationId>(...))`.
- Static files: `StaticDataClient.get(.getBis(build:spec:))` on iOS, `StaticEndpoints.getBis(build, spec)` on Android.

**Strings.** Add to `en.json` and run `node web/scripts/gen-mobile-copy.mjs`. Read them as `Copy.<camelKey>` on iOS and `R.string.<key_with_underscores>` on Android.

**Links.** Edit `apps/shared/links.json` and run `node web/scripts/gen-mobile-links.mjs`.

**Feature switches.** Add the key to `apps/shared/features.json` and run `node web/scripts/gen-mobile-features.mjs`. Gate the screen on `appConfig.isEnabled(.key)`.

## Concerns

1. **A3's fixture names.**
   - A3's branch names its fixtures `characters-home*.json` and `app-config.json`, and its `api/internal/app/contract_test.go` reads those names.
   - Main now has them as `character.home*.json` and `app.config.json`, following lane C's convention.
   - When A3 merges, point its test at the new names and drop its copies. The spec's `x-fixtures` claims only the new names, so leftover files fail `TestEveryFixtureIsClaimedByTheSpec`.
2. **A3 does not send `features`.**
   - Until A3 adds the field above, the live config answer lacks `features`.
   - The apps take their bundled defaults then.
   - Once A3's contract test reads the updated `app.config` fixture, it fails on the missing `features` until the field is added.
3. **Copy needing an owner call.**
   - `raid.breakdown` ("{t} tanks · {h} healers · …") reads "1 tanks" with one tank. The spec's copy is kept as written, marked `notPlural`.
   - The word-only plurals (upgrades, kills, wipes, new bests) now carry their count: "11 upgrades", "3 kills". The String Catalog refuses a plural that does not show the number.
4. **The Android client sends the device token on every call.** Only iOS honours `x-authenticated: false`.
   - It is harmless: the exchange runs before a token exists, and config is public.
   - Android's `Endpoint` could carry the flag if the owner wants parity.
5. **What the spec leaves open.**
   - These are left as open JSON: `/v1/me` guild `claim`, `verify`, `covered` and `subscribe`; the seat blocks; and the raid view's `report`.
   - The fixtures show these only as null, or the v1 apps do not read them.
   - A feature lane that needs one types it in the spec and regenerates.
6. **`openapi.yaml` grew to about 4,600 lines.** The engine's `SimResult` tree is generated too, because the sims result route returns it.
