# Lifecycle walk, round 4 (20 Oct 2026, 20:2x CDT): the guild master's path on the seeded local stack

The owner's characters are guild members, so the guild master's claim and everything behind it had only ever run under Playwright fixtures. Lane G.2 built `tools/dev-stack/` (a real Postgres and the real API in WSL, the real site on `localhost:4321`, a dev sign-in gated to loopback) and seeded one unclaimed guild, **Lifecycle Test** (`us/pvp/lifecycle-test`): the guild master Bow Jackzon on `hunthrop#1894`, an officer on `Ashenveil#2201`, three members on `Quillfeather#3301`, a stranger on `Wanderer#4401`, a roster snapshot, one export per character and one Onyxia report. The walk follows `docs/superpowers/reviews/lifecycle/r4/local-stack.md` step by step in the desktop app's browser pane; captures sit beside this file.

## What the guild master's path adds up to

The mechanics all work with the real API: claim, approve one and approve all, settings save, invite rotate and join, award, consent, leave, the officer's view, the public view. What fails a first-time guild master is what the pages say and do not say: three tabs end in design notes written for this project ("NEEDS NEW DATA", a file path, "unchanged from round 1", "no network path to the addon"); the site's private cache hides a join, a plan grant and an approval count until the player clears storage or waits; the invite page names no guild; the claim page offers "Contest" against nothing and gives no next step; the roster is the verified accounts only, so an invited member and the in-game-only names never appear; plurals, raw ISO dates, "BeastMastery", "DPSRootbound", "+0 DPS", "consent needed" and "not sim-checked" on every row; one-click Leave and Award with no confirmation. The stack and seed are reusable (`tools/dev-stack/`), so every fix can be re-walked here before it ships.
