## Content (three sonnet subagents, one round, three classes each, in parallel)

- Group A: Warrior, Paladin, Hunter
- Group B: Rogue, Priest, Shaman
- Group C: Mage, Warlock, Druid

Each subagent gets: the full rule set from the dispatch (voice, no-copy check, sourcing,
cross-check, beta honesty, vocabulary), the nine-section list and order, the data file paths
above, its three classes' existing single-page guide content, and a report file to write
per-guide confidence and the sources used. Each subagent writes
`web/src/content/guides/<class>/index.md` and `web/src/content/guides/<class>/<spec>.md` for
every spec of its three classes directly, then deletes the old flat
`web/src/content/guides/<class>.md`.

I review every class's files against rules 1–5 myself (overlap check, three spot-checked
facts per guide) before committing. One commit per class (`content(guides): <class> spec
guides and landing page`), after `web/src/content.config.ts` + routing + tests are committed
first as infra.
