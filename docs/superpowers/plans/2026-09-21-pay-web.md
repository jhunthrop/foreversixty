**Goal:** Build the Web lane of the entitlements-and-payments spec: `/premium` (static, no
client JS, monthly/yearly toggle, honest tiers + FAQ), `/premium/checkout` (one small hydrated
island that talks to `POST /v1/billing/checkout` / `/v1/billing/portal`), every existing
premium control updated to read the new `Entitlements` shape, the account page's billing
block, `/terms` `/privacy` `/refunds`, and the footer links — all stubbed against the API
lane's not-yet-landed shapes via `page.route`/`vi.stubGlobal`.

**Architecture:** A small `web/src/lib/billing/` module (plans data, copy, API client) is the
single source of truth for prices and billing copy. `/premium` is pure Astro markup with a
CSS-only (`:target`) interval toggle and plain `<a>` buy links — no framework runtime.
`/premium/checkout` is a `session` page that hydrates one island, `CheckoutLauncher.svelte`,
which does the actual `fetch`. Every existing "premium" reader (`SimView.svelte`,
`ToolsView.svelte`, `RunControl.svelte`, `BulkRunBar.svelte`, `Account.svelte`) is updated to
read `Me.entitlements` with a fallback to the still-present, now-optional `Me.user.premium`
so this lane does not need the API lane to land first and does not break other lanes' existing
e2e fixtures that still stub the old shape.

**Tech Stack:** Astro (static pages, content collections), Svelte 5 runes (one island),
Tailwind utility classes matching `design/DESIGN-SYSTEM.md`, Vitest (unit/component),
Playwright (e2e, `E2E_PORT=4441`).

**Spec:** `docs/superpowers/specs/2026-09-21-entitlements-and-payments-design.md` (binding;
§5 "Web", §6 "Legal pages", §1.4 "GET /v1/me's new shape", §4 "API endpoints" for request/
response shapes) and `docs/superpowers/specs/2026-09-21-guild-and-premium-proposal.md` (prices,
principles, no-ads decision, COMMISH LLC).

## Global Constraints

- Prices: Premium $4/month or $40/year; Guild $15/month or $150/year (covers every member).
  One data file (`billing/plans.ts`) is the only place a price literal is written; every other
  string is built from it.
- No ads, ever, for anyone — stated on `/premium` verbatim, not as a perk.
- Honest copy: no exclamation marks, no urgency, no fake discounts, secondary buttons only
  (`SECONDARY_BUTTON`/`SECONDARY_BUTTON_FIXED` from `web/src/lib/planner/styles.ts`), no
  marketing hero. Mark each benefit available-now vs. coming per what actually exists today
  (server sims exist behind `users.premium`/`entitlements`; officer tools do not).
- Nothing implies an armory/Battle.net-backed feature is paid (Blizzard developer-terms
  constraint) — `/premium` states the opposite explicitly.
- `/pricing` resolves to `/premium` (one redirect page, no separate content).
- The API has not landed and no Stripe keys exist. Every network call goes through
  `billing/api.ts` against the spec's documented shapes; e2e stubs the API with `page.route`;
  unit tests stub `fetch` with `vi.stubGlobal`. A `503 billing_unavailable` (or any billing
  API failure) is handled honestly: no dead-end redirect, a plain sentence, no button that
  promises something that fails.
- Never send a price id or amount from the client — `billing/api.ts` sends only
  `{plan, interval, guild_id?, intent?}`; the server resolves the price.
- Never render a query-string value into the page unescaped. `/premium/checkout` parses
  `plan`/`interval`/`guild_id`/`status`/`session_id` server-side in Astro frontmatter,
  validates each against a closed enum/shape, and passes only the validated, typed values as
  component props — an invalid value renders the honest "something's wrong" state, never the
  raw string.
- The success return is "payment is being confirmed" until `GET /v1/me` (via `fetchMeOnce`)
  shows the entitlement — never inferred from `?status=success` alone.
- Content pages ship no client JavaScript. `/premium` and the legal pages pass no `session`

## Ruling ledger (recorded here; also written into the SDD progress ledger per task)

- **Ruling A — `Me.user.premium` stays, as optional, rather than being removed now.** The
  spec's §5.3 says it is removed; that assumes the API lane lands the new `entitlements` shape
  in the same window. It has not. Other lanes' e2e fixtures across `web/tests/e2e/` (not owned
  by this lane) still stub `user: { premium: true|false, ... }` with no `entitlements` key.
  Every reader computes effective server-sims access as `me?.entitlements?.server_sims ??
  me?.user.premium === true`, so both the old stubs (pre-existing, other lanes) and the new
  shape (this lane's own new tests) work unmodified. *Cost if wrong:* a trivial fallback
  expression to delete once the API lane ships and every fixture is migrated at
  reconciliation — not a design commitment either lane needs to unwind.
- **Ruling B — `login.astro` gains a `next` query param, read and validated server-side.**
  It does not exist today (`next` is hardcoded to `/logs`), but "signed out, the buy control
  leads to sign-in and returns to the premium page" requires it, and no other lane provides it.
  A new `web/src/lib/account/safe-next.ts` (`safeNextPath`) enforces "same-site path, no
  scheme, no host" — the same contract `auth.safeNext` enforces server-side — before the value
  ever reaches `battlenetStartUrl`. *Cost if wrong:* a two-line Astro frontmatter change and
  one new 15-line helper module; if another lane also touches `login.astro`, a coordinator
  merge conflict, not a behavior bug (this makes `next` more capable, never less).
- **Ruling C — the guild-plan `409 conflict` message on `/premium/checkout` names "the
  guild's settings page" without a deep link.** The spec's own guild-subscribe URL
  (`/premium/checkout?plan=guild&interval=monthly&guild_id=<id>`) carries only a numeric
  `guild_id`, not the region/ruleset/name `guildHref` needs to build a real link, and
  `GuildSettings.svelte` (guild-membership lane's file) is out of this lane's ownership to
  change. *Cost if wrong:* one honest sentence instead of a clickable link on a rare
  already-subscribed path — cheap to upgrade later by having the guild-subscribe button also
  pass `guild_slug`.
- **Ruling D — the legal pages render always (no `draft`-gated 404) and show an "unfinished
  draft" banner directly in their own Markdown while any `OWNER:` marker remains**, per this
  lane's explicit dispatch instruction, which supersedes the spec §8's `draft: true`/exclude-
  from-`getStaticPaths` mechanism for this lane. The production-build gate is a separate unit
  test keyed on `LEGAL_PAGES_FINAL=1` (§6 below), not route exclusion. *Cost if wrong:* the
  coordinator prefers the spec's literal 404-until-ready mechanism — a one-line frontmatter
  field (`draft`) and a `getStaticPaths` filter to add later; the content and the marker text
  do not change either way.
- **Ruling E — `capPremiumNote`/`premiumRequired` gain a real `<a href="/premium">` element
  in the component template, not an HTML string embedded in the copy constant.** The spec's
  prose shows the link inside the copy string; every existing render site interpolates copy as
  plain text (`{copy.thing}`, never `{@html}`), and introducing `{@html}` for one string is a
  bigger, riskier change than adding one sibling `<a>` next to the existing text. *Cost if
  wrong:* copy and markup are two edits instead of one if this ever needs to move — no
  behavior difference to a reader.

```ts
// web/src/lib/billing/plans.ts
// The one place a Forever Sixty price literal is written. Every plan-facing copy string
// (billing/copy.ts) and every checkout link builds its price text from here, per the
// coordinator's "single data file, no price literal repeated in copy" instruction.
export type PlanKey = 'premium' | 'guild';
export type Interval = 'monthly' | 'yearly';

export interface Plan {
  key: PlanKey;
  name: string;
  monthly: number;
  yearly: number;
  /** True for the guild plan: one subscription covers every member, not just the buyer. */
  coversGuild: boolean;
}

export const PLANS: Record<PlanKey, Plan> = {
  premium: { key: 'premium', name: 'Premium', monthly: 4, yearly: 40, coversGuild: false },
  guild: { key: 'guild', name: 'Guild', monthly: 15, yearly: 150, coversGuild: true },
};

export function formatPrice(amountUsd: number, interval: Interval): string {
  return `$${amountUsd}/${interval === 'monthly' ? 'month' : 'year'}`;
}
```

```ts
// Every browser call to the billing half of the API (spec section 4). Mirrors guild/api.ts's
// pattern exactly: the shared transport (account/api.ts's requestEnvelope), a module-local
// error class carrying the HTTP status so a caller can branch on 503 (billing not configured
// yet) or 409 (a guild already has the plan) without parsing a message string.
import { AccountError, requestEnvelope, type EnvelopeResult } from '../account/api';
import { API_BASE_URL } from '../planner/config';
import type { Interval, PlanKey } from './plans';

export const BILLING_API_FAILED = 'That did not work; try again';

export class BillingApiError extends Error {
  constructor(
    message: string,
    readonly status: number,
  ) {
    super(message);
    this.name = 'BillingApiError';
  }
}

async function call<T>(
  path: string,
  apiBase: string,
  init: { method?: string; body?: unknown } = {},
): Promise<T> {
  let result: EnvelopeResult<T>;
  try {
    result = await requestEnvelope<T>(path, apiBase, { ...init, failureMessage: BILLING_API_FAILED });
  } catch (error) {
    if (error instanceof AccountError) throw new BillingApiError(error.message, error.status);
    throw new BillingApiError(BILLING_API_FAILED, 0);
  }
  if (result.data === null) throw new BillingApiError(result.message ?? BILLING_API_FAILED, result.status);
  return result.data;
}

  interval: Interval;
  /** Required by the API when plan is 'guild'; omitted for a personal premium purchase. */
  guildId?: number;
  /** Only ever sent from the guild settings page's "Take over billing" button. */
  intent?: 'transfer';
}

export interface CheckoutResult {
  checkout_url: string;
}

export interface PortalResult {
  portal_url: string;
}

export function startCheckout(input: CheckoutRequest, apiBase: string = API_BASE_URL): Promise<CheckoutResult> {
  const body: Record<string, unknown> = { plan: input.plan, interval: input.interval };
  if (input.guildId !== undefined) body.guild_id = input.guildId;
  if (input.intent !== undefined) body.intent = input.intent;
  return call<CheckoutResult>('/v1/billing/checkout', apiBase, { method: 'POST', body });
}

export function openPortal(guildId: number | undefined, apiBase: string = API_BASE_URL): Promise<PortalResult> {
  const body = guildId === undefined ? {} : { guild_id: guildId };
```

```ts
// web/src/lib/account/safe-next.ts
// The client-side half of the same contract the API's auth.safeNext (bnet.go:142) enforces
// server-side: a `next` value must be a same-site path, with no scheme and no host. Used
// wherever a page reads `next` out of its own query string before handing it to
// battlenetStartUrl or building a /login link -- so a crafted `?next=` can only ever send a
// visitor back to a path on this site, never off it.
export function safeNextPath(raw: string | null | undefined, fallback: string): string {
  if (raw === null || raw === undefined || raw === '') return fallback;
  if (!raw.startsWith('/')) return fallback;
  if (raw.startsWith('//') || raw.startsWith('/\\')) return fallback;
  // A scheme (e.g. "javascript:") is only a real risk before the first '/', but the leading
  // '/' check above already rejects "javascript:alert(1)" as not starting with '/'. This
  // second check catches a same-site-looking path that still smuggles a colon-scheme via an
  // encoded or backslash variant a browser might normalise.
  if (/^\/[a-zA-Z][a-zA-Z0-9+.-]*:/.test(raw)) return fallback;
  return raw;
}
```

```svelte
<!-- The one small hydrated island /premium/checkout mounts. On mount: signed out goes
     straight to /login?next=<this exact url>; signed in posts /v1/billing/checkout and
     redirects to the returned checkout_url. A ?status=success return re-fetches /v1/me
     (never trusts the query string) and shows "confirmed" only once entitlements says so,
     polling briefly if the webhook has not landed yet. -->
<script lang="ts">
  import { fetchMeOnce } from '../lib/account/api';
  import { BillingApiError, startCheckout } from '../lib/billing/api';
  import { checkoutCopy } from '../lib/billing/copy';
  import { safeNextPath } from '../lib/account/safe-next';
  import type { Interval, PlanKey } from '../lib/billing/plans';

  let {
    plan,
    interval,
    guildId,
    status,
  }: {
    plan: PlanKey;
    interval: Interval;
    guildId?: number;
    status?: 'success' | 'canceled' | null;
  } = $props();

  let message = $state(checkoutCopy.redirecting);
  let showRetry = $state(false);

  const POLL_INTERVAL_MS = 1500;
  const POLL_ATTEMPTS = 4;

  function currentUrl(): string {
    return window.location.pathname + window.location.search;
  }

  async function pollForEntitlement(): Promise<void> {
    message = checkoutCopy.processing;
    for (let attempt = 0; attempt < POLL_ATTEMPTS; attempt += 1) {
      const me = await fetchMeOnce();
      const entitled =
        plan === 'premium' ? me?.entitlements?.server_sims === true : me?.entitlements !== undefined;
      if (entitled) {
        message = checkoutCopy.confirmed;
        return;
      }
      if (attempt < POLL_ATTEMPTS - 1) await new Promise((r) => setTimeout(r, POLL_INTERVAL_MS));
    }
    message = checkoutCopy.confirmationSlow;
  }

  async function launch(): Promise<void> {
    const me = await fetchMeOnce();
    if (me === null) {
      window.location.assign(`/login?next=${encodeURIComponent(safeNextPath(currentUrl(), '/premium'))}`);
      return;
    }
    if (status === 'success') {
      void pollForEntitlement();
      return;
    }
    try {
      const result = await startCheckout({ plan, interval, guildId });
      window.location.assign(result.checkout_url);
    } catch (error) {
      showRetry = false;
      if (error instanceof BillingApiError) {
        if (error.status === 503) {
          message = checkoutCopy.notOpenYet;
        } else if (error.status === 409) {
          message = checkoutCopy.guildAlreadyOnPlan;
        } else {
          message = checkoutCopy.genericFailure;
          showRetry = true;
        }
      } else {
        message = checkoutCopy.genericFailure;
        showRetry = true;
      }
    }
  }

  $effect(() => {
    void launch();
  });
</script>

<div class="flex flex-col gap-3">
  <p class="min-h-[21px] text-[14px]" role="alert" data-testid="checkout-message">{message}</p>
  {#if showRetry}
    <button
      type="button"
      class="border-line-warm-strong text-strong w-fit px-4"
      onclick={() => void launch()}
    >
      {checkoutCopy.retry}
    </button>
  {/if}
</div>
```
