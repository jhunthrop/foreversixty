# The cut, the header and the redirects — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the wiki (Classes/Zones/Dungeons/search/three wiki pages), cut the header down
to five doors plus "Get set up" and an account menu, ship `/setup` in place of `/addon`, 301
every removed URL, and fix the three named bugs — spec section 3, lane A.

**Architecture:** Astro content pages and their collections are deleted outright (no hidden
flags); `lib/nav.ts` becomes the single source the header reads; `SessionNav.svelte` is
replaced by `AccountMenu.svelte` (a `<details>`-based avatar/menu island reusing
`createQueryState` for the session read, the same pattern `SessionNav.svelte` used);
`web/public/_redirects` is a new static file Cloudflare Pages reads directly, proven by a new
Playwright spec that reads its contents (Astro preview does not serve it) and a build-time
Node script that fails the build if a removed route still exists under `dist/`.

**Tech Stack:** Astro 7 (content collections, `astro:container` for SSR unit tests), Svelte 5
(runes), Vitest, Playwright, Tailwind v4, Cloudflare Pages `_redirects`.

**Spec:** `docs/superpowers/specs/2026-09-25-product-not-wiki-design.md` (sections 1, 2, 3
bind this plan; section 8 names this lane's file ownership; section 9 names the required
tests).

```typescript
// The one source of the primary nav's structure: labels, hrefs, and "is this page current"
// logic. Header.astro renders from this; Header.test.ts asserts against it directly, so a
// reordering shows up as a data-level test failure rather than a markup diff.

export interface NavItem {
  readonly label: string;
  readonly href: string;
}

/** The five doors, in this order on every breakpoint (spec 2026-09-25, section 2). */
export const PRIMARY_NAV_ITEMS: readonly NavItem[] = [
  { label: 'Planner', href: '/planner' },
  { label: 'Simulator', href: '/sim' },
  { label: 'Logs', href: '/logs' },
  { label: 'Rankings', href: '/rankings' },
  { label: 'Guides', href: '/guides' },
];

/** The sixth, quieter item at the end of the row (spec section 2). */
export const SETUP_NAV_ITEM: NavItem = { label: 'Get set up', href: '/setup' };

/** The items after the five doors, in order. One entry today; kept as an array (rather than
 *  inlining SETUP_NAV_ITEM at the call site) so Header.astro's render loop needs no special
 *  case if a second trailing item is ever added. */
export const TRAILING_NAV_ITEMS: readonly NavItem[] = [SETUP_NAV_ITEM];

/**
 * True for the item's own page and any sub-path of it (`/sim` matches `/sim/gear`), so a
 * tool's own sub-pages (the sim tab strip, a saved permalink) still mark the top-level nav
 * entry current. Never matches a different page that merely shares a prefix (`/planner`
 * does not match `/plannerx`).
 */
export function isNavItemCurrent(item: NavItem, path: string): boolean {
  return path === item.href || path.startsWith(`${item.href}/`);
}
```
