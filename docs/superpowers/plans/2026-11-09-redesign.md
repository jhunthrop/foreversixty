# Redesign Implementation Plan (the Forever look, web and apps)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** move the live site and both apps onto the redesign the owner approved on 2026-11-08 ("yes do what you need to do"). That means:
- Blizzard's Forever palette, with Marcellus over Open Sans.
- Their floating rounded nav, with Premium as their teal Subscribe.
- The owner's painted grounds and bands; soft rounded panels, with the framed and ornate frames on two or three elements a page.
- The client tooltip, and BiS on the owner's paperdoll frame.

The system changes in place, never forked.

**Architecture:** one design-system lane changes the shared layer first:
- tokens (`design/tokens/tokens.json`, already generated to web, iOS and Android);
- fonts, art assets, the shell (Base, Header, Footer) and the shared components.

It lands alone. Page lanes then restyle one page each against its mock, in the order below. The mobile lanes follow from the same tokens.

**Tech Stack:** Astro 5, Svelte 5 and Tailwind; vitest, Playwright (the parity specs) and lhci. SwiftUI and Compose consume the generated tokens.

**Spec:** `design/specs/2026-11-09-directions.md` is the authority (round 5, Premium, Logo, Paperdoll, Tab-bar icons, Mobile, and round 4 sections 2 to 6). The flows are in `design/specs/2026-11-08-app-flows.md`.

**Mocks:** `design/mocks/directions/`. The generators are `style.py`, `pages.py`, `paperdoll.py`, `mobile.py` and `art.py`. Captures are in `png/`, and the gallery is `~/Desktop/forever-design-directions/index.html`.

## Global Constraints

- **Tenets** (`docs/tenets.md`):
  - the best-addon standard;
  - 44 px targets;
  - no layout shift, with the reserves pinned by `layout-reserve.test.ts`;
  - full-bleed bands and centred max-width containers;
  - captures at 390, 1024, 1440 and 2000 (the owner reads at about 2000).
- **The crest rule changes in one place only.** The paperdoll medallion and the signed-in centre take Battle.net media. Every other character image stays the ringed crest.
- **Blizzard media are referenced by URL, never committed.** This covers `characters.render_url` and `characters.avatar_url`, along with test fixtures and captures that show them.
- **The not-official distinction stays.** The seal and "Forever Sixty" lead the bar, and the footer keeps "A fan-made player tool. Not affiliated with Blizzard." The link preview carries the name (ux-designer).
- **Copy:** no em dashes. A number takes its unit and nothing else (ai-slop tell 22).
- **Budgets:** `web/lighthouserc.json` and `web/scripts/asset-budget.mjs` hold. The art ships as AVIF with WebP fallback, sized per use. Fonts must not push LCP.
- **Landing (owner rules):**
  - Lanes never push and run only their touched tests.
  - One integrator merges, regenerates, runs every gate and pushes to main once (no PRs).
  - A lane that touches Base.astro, a layout or the header runs the full web vitest, the full Playwright suite and the lhci shard.
- **Parity (tenet 15, `design/parity.md`):** every page lands with its mock as the reference. The parity generator (`design/mocks/ws_*.py`) carries the structure and the regions; the directions mock carries the look. Each page lane brings the two together (see Task S9), and the build must match at the 8 px / 5% box tolerance. ux-designer, wow-player and ai-slop-reviewer read the build captures and SHIP before landing.
- **Design before build:** every surface marked "needs mock" in the surface table gets its directions mock first. The design lane mocks them in four batches, each reviewed by the three reviewers and landed on its own. A page lane starts when its batch is on main, never before.
- **Shared components are first class (owner, 2026-11-08: "we should use shared components and resources as a first class citizen where we can").** Every page composes from the shared inventory below. A pattern a page needs that is not in it goes into the shared library first, through the design-system lane. The mocks draw each primitive once (`design/mocks/directions/style.py` and its successors) and reuse it on every surface: one item row, one panel, one title band, one chart frame.

## Review Focus

1. **Shared-layer churn.** Legacy Direction B tokens are still read by `BUTTON_PRIMARY` and others. Task S1 keeps them aliased until the sweep (Task P15) deletes them, so no page breaks between waves.
2. **Ground repeat on wide screens.** Check one capture at 2560 per page with a large empty brown area (the tier list is the worst case).
3. **Nav overflow.** A long name with the level overflowed the mock bar by 25 px. The built bar folds into Menu wherever it would overflow, and the test is written against the longest fixture name.
4. **Paperdoll performance.** The frame is a 2x image under every BiS page. It must not become the LCP element on phone, where the list form shows instead.
5. **Battle.net media failures.** Media can 403 (as `-inset.jpg` does), 404 or never be captured. The medallion falls back to the seal and the centre to no model, with no broken image and no shift.
6. **Per-page variants creeping back.** A page lane that restyles a row or a chart locally instead of using the shared one. The library test (Task S6) and the review read check it.

## Guard rails

- **One system.** A page lane that needs a new primitive stops and asks the integrator to add it to the S layer. It never adds a page-local copy.
- **The mocks are references, not sources.** No mock HTML or data URI ships. The art ships only from S3's outputs.
- **The generated files are never hand-edited:** `tokens.css`, `DesignTokens.swift`, `Tokens.kt`, the art manifest and the copy outputs.
- **Media fallbacks are tested, not assumed:** avatar to seal, render to no model, and the -inset 403.
- **Each wave's gate is the integrator's full run.** No page lane starts on a red S layer.
