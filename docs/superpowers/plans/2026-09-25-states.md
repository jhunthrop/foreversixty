## Ledger of rulings made while writing this plan

(Copied into `.superpowers/sdd/2026-09-25-states/progress.md` verbatim as the ledger's
first entries; new rulings made during execution are appended there, not here.)

1. **Rankings empty state applies to both boards.** Spec quotes one message for "rankings
   with no data" ("No ranked fights yet for this filter. Rankings fill in as reports are
   uploaded." + Upload a log). Applied verbatim to both the character board's empty result
   and the guild board's empty result (both are "no data because nothing has been
   uploaded yet"), replacing their current bare-message `EmptyState` calls. Cost if wrong:
   trivial copy tweak.
2. **"Your sims" empty state gets `EmptyState`, no action.** `SimHistory.svelte`'s empty
   line ("Nothing saved yet. Run a sim and press Save.") is ad-hoc text today, violating
   "never ad-hoc text" — converted to `EmptyState` with no `action`, because the action
   ("run a sim") is the Run button already on the same page, and a second link back to the
   same page a visitor is already on would be circular. Cost if wrong: add a `Run Top Gear`
   or similar action later, one line.
3. **The account's ratings empty state gets an action.** `CharacterRatingPanel.svelte`'s
   `EmptyState` (added by lane A for spec 3.6, message only) is missing the "exactly one
   action" this lane's hard rule requires. Added `{ label: 'Upload a log', href: '/logs' }`,
   matching `MyReports.svelte`'s own reports-empty action, since a ranked fight comes from
   an uploaded report. Cost if wrong: the action target is one `href` to change.
4. **Guild roster empty state: officer gets an action, member does not.** The officer copy
   ("Share the invite link...") names an action a member cannot take; pointed it at
   `guildSettingsHref(...)` (where the invite link lives). The member copy names no action
   that exists for a member, so it keeps none — "at most one," not "exactly one," where
   nothing legitimate exists. Cost if wrong: one href to retarget.
5. **Planner "bare build" = no current-character pointer.** `Planner.svelte` already tracks
   `pointer: CurrentCharacter | null` (the same concept `CurrentCharacterChip` shows
   everywhere else). "Level shown only when a character is loaded" is implemented as
   `pointer !== null`, computed identically for the standalone `/planner`/`/b/:id` mount and
   the non-standalone Top Gear embed (`TalentCandidates.svelte`'s inline planner), rather
   than inventing a second, competing "loaded" concept keyed on `store.spent > 0`. Cost if
   wrong: one boolean expression to change in one place (`Planner.svelte`).
6. **After-sim upgrade sentence: sourced from a small localStorage record, not a fetch.**
   "Nothing fetched anew" rules out asking the API whether a Droptimizer result exists for
   this character. `Droptimizer.svelte` (`/sim/drops`) already holds the full `BulkResult`
   client-side the moment a run finishes; it writes the top upgrade row (item name, source,
   gain) to a new `lib/sim/last-upgrade.ts` localStorage slot (same try/catch/JSON pattern as
   `current-character.ts`). `SimView.svelte` reads it once, on mount (no reactive re-read,
   same one-shot pattern as `readCurrent()`), and passes it to `SimResults.svelte` as a
   prop. This is genuinely "data the run already produced" — a *previous* Droptimizer run,
   read back with no network call. Global (not per-character) slot, for simplicity; a stale
   entry from a different character is an acceptable, honestly-labelled small imprecision
   (it still names a real upgrade a real run produced) rather than a reason to fetch.
   Cost if wrong: scope the key to the character (one more field, one more comparison).
7. **The `/sim` intro-sentence merge does NOT touch the shared `ScopeNote.astro`.**
   `ScopeNote.astro` is used by all seven simulator page shells and is covered by
   `tests/e2e/sim-scope.spec.ts`'s seven-page loop and `ScopeNote.test.ts`. Spec 6's caveat
   ("one line under the character list") and the hard rule's own citation
   ("`pages/sim.astro`'s shell", "`/sim`'s Lighthouse numbers") both name `/sim` only.
   Changing the shared partial would silently rewrite six unrelated tool pages this lane has
   no mandate over. Instead: `/sim` stops rendering `<ScopeNote />` and renders its own
   merged line (new `landingCopy.scopeCaveat`); the other six pages keep `ScopeNote.astro`
   and its original two sentences, completely unchanged. `simCopy.scopeNote` and
   `handoffCopy.belowSixtyFraming` are left untouched (so `SourceSwitcher.svelte`'s own
   separate, deeper-in-the-page repetition of the scope sentence, tested by
   `sim-scope.spec.ts`'s "carries the sentence a second time" test, needs no change either).
   Cost if wrong: this is the ruling most worth a second look in review — flagged for the
   task reviewer specifically.
8. **Logs companion column keeps the pairing island; loses the download links and the
   `/combatlog` reminder to a pointer paragraph.** `pages/setup.astro` does not yet wire up
   `<Account mode="pairing">` (a gap in lane A's own step 3, out of this lane's named
   scope — `pages/setup.astro` is not in section 8's row D). Deleting the pairing island
   from `logs.astro` with no replacement would remove real functionality
   (`tests/e2e/logs-upload.spec.ts`'s pairing-code test) with nothing to replace it. Spec
   3.4's own wording only calls out "repeating the download panel" as the redundant part.
   So: the companion column keeps its pairing island (`<Account mode="pairing">`) and gains
   one paragraph pointing to `/setup` for downloads and the `/combatlog` step; the "1./2./3."
   numbered-steps framing is dropped since only one action (pairing) remains on this page.
   Cost if wrong: re-add the download block; the pairing island is untouched either way.

```ts
// web/src/lib/sim/last-upgrade.ts
// The most recent Droptimizer top-row upgrade a run produced, in localStorage -- read back
// by the plain /sim results card (spec 2026-09-25 §6's after-sim sentence) with no network
// call: "nothing fetched anew, nothing invented." Written by Droptimizer.svelte the moment
// a /sim/drops run finishes with a real upgrade. Same try/catch/JSON pattern as
// current-character.ts: a convenience, never a source of truth, safe to import during
// SSR/prerender since nothing here touches `window`/`localStorage` at import time.
export interface LastUpgrade {
  itemName: string;
  sourceName: string;
  /** Already formatted, e.g. "+14 ± 3" -- combos.ts's own deltaLabel(). */
  gain: string;
  savedAt: string; // ISO
}

const STORAGE_KEY = 'fs.lastDroptimizerUpgrade';

function storageOf(storage: Storage | undefined): Storage | null {
  if (storage !== undefined) return storage;
  try {
    return globalThis.localStorage ?? null;
  } catch {
    return null;
  }
}

function isLastUpgrade(value: unknown): value is LastUpgrade {
  if (typeof value !== 'object' || value === null) return false;
  const candidate = value as Record<string, unknown>;
  return (
    typeof candidate.itemName === 'string' &&
    typeof candidate.sourceName === 'string' &&
    typeof candidate.gain === 'string' &&
    typeof candidate.savedAt === 'string'
  );
}

export function readLastUpgrade(storage?: Storage): LastUpgrade | null {
  const target = storageOf(storage);
  if (target === null) return null;
  try {
    const raw = target.getItem(STORAGE_KEY);
    if (raw === null) return null;
    const parsed: unknown = JSON.parse(raw);
    return isLastUpgrade(parsed) ? parsed : null;
  } catch {
    return null;
  }
}

export function writeLastUpgrade(value: LastUpgrade, storage?: Storage): void {
  const target = storageOf(storage);
  if (target === null) return;
  try {
    target.setItem(STORAGE_KEY, JSON.stringify(value));
  } catch {
    // Private browsing, quota exceeded, or a disabled storage API: this is a convenience,
    // so a failed write is silently skipped, same as current-character.ts's writeCurrent.
  }
}
```
