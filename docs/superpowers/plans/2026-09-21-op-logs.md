# Op-logs: logs discoverability and its API work

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Spec section 4, all of it — a public, unauthenticated `GET /v1/reports/recent`
feed; a "Recent public reports" panel on `/logs` above "Your reports" plus a compact,
self-contained version for the homepage; an encounter picker on `/rankings` so the
Characters board never demands an encounter a bare visitor cannot name; one line of
framing copy on `/logs` for a visitor who is not raiding yet; and a fix for the Share
"gear invalid" 400 a journey reviewer hit on the Simfury test character.

**Spec:** `docs/superpowers/specs/2026-09-21-one-product-design.md` section 4 (binds this
lane) and section 0 (binds every lane).

## Tasks

- [x] **Task 1 — `GET /v1/reports/recent` (API).** Public, unauthenticated, mounted
      alongside the other report routes (`api/internal/reports/handler.go`, `recent.go`).
      Newest `visibility = 'public'` and `status = 'complete'` reports; fields id, title
      (server-resolved to zone when empty), created_at, fight_count, kill_count,
      guild_name (omitted when none). Never reads the owner at all, so `anonymize`
      cannot leak through it. Page size 10 (`RecentPerPage`), opaque keyset cursor over
      `(created_at, id)` (`recentCursor`, base64 of `RFC3339Nano|id`). `Store.Recent` in
      `store.go`; handler + store tests in `recent_test.go`, seeding rows directly via a
      new `harness.seedReport` helper.
      Migration `0017_reports_recent_idx`: a partial index on
      `(created_at desc, id desc) where visibility = 'public' and status = 'complete'` —
      neither existing reports index covers this filter, and the migration comment
      records the reasoning in place of a live `EXPLAIN` (no Postgres available in this
      environment; see the ledger).

- [x] **Task 2 — shared report row + "Recent public reports" panel (`/logs`).**
      Extract `MyReports.svelte`'s row markup into `web/src/components/ReportRow.svelte`
      (`href`, `title`, `createdAt`, `fightCount`, `killCount`, `meta`, `status`);
      `MyReports.svelte` now renders it instead of its own `<li>`. New
      `web/src/lib/reports/recent.ts` (`fetchRecentReports`, mirroring
      `lib/rankings/api.ts`'s `credentials: 'omit'` pattern) and
      `web/src/lib/reports/copy.ts` (every visible string). New
      `web/src/components/RecentReports.svelte`, `compact` and `heading` props (the
      latter mirrors `MyReports`'s own convention for a panel that already has a title).
      Mounted on `/logs` inside a `Panel title="Recent public reports"` above "Your
      reports", `heading={false}`. Homepage mount is Lane A's: see the final report for
      the one line to add.

- [x] **Task 3 — `/logs` framing line.** `logsFraming` in `lib/reports/copy.ts`,
      rendered under the page's opening paragraph.

- [x] **Task 4 — `GET /v1/encounters` + `/rankings` encounter picker.** The store method
      (`rankings.Store.Encounters`) already existed with its own test; add the HTTP
      route (`rankings/handler.go`) and a handler test (`encounters_test.go`). Web:
      `fetchEncounters` in `lib/rankings/api.ts`, `requiresEncounter(state)` (pure, in
      `lib/rankings/url.ts` — true for the Characters board always, and for the Guilds
      board's speed/execution kinds, false for progress) and `encounterPickerCopy`.
      `Rankings.svelte`: a `needsPicker` derived value gates the existing fetch effect;
      when true, the network call is skipped and the picker (or, with no encounters at
      all, the honest empty state plus a button into the Guilds board) renders instead.

- [x] **Task 5 — Share "gear invalid" fix.** Root cause: `trees.Item` carried no
      `two_hand` flag, so `builds.validateGear` required an exact slot match and refused
      every one-handed weapon placed in `off_hand` — the data pipeline tags every
      one-hander's canonical slot `main_hand`. Reproduced with item 18827 (Grand
      Marshal's Handaxe) from the Simfury export in
      `.superpowers/journeys/profiles.md`. Fix: `trees.Item.TwoHand`
      (`json:"two_hand"`) plus `builds.fitsSlot`, which additionally accepts a
      `main_hand`-tagged, non-two-handed item in `off_hand`; the main_hand/off_hand pair
      joins the existing unique-item dual-equip check. Regression tests in
      `builds/validate_test.go` using the real item id, plus two new fixture items
      (a one-hander and a two-hander) in `trees/testdata/builds/test-1/items/warrior.json`.
