# Addon hub build plan

> **For agentic workers:** one lane per section below, each in its own worktree from `origin/main`. Lanes never push; one integrator merges, bumps the addon version once, runs the gates and pushes (the batch-landing rule). Each lane runs only the busted specs it touches (`cd addon && busted tests/<spec>.lua`) plus `luacheck` on its files; the integrator runs the full `addon-release.yml` checks once.

**Goal:** the addon becomes one window with tabs (Me, Builds, Gear, Rotation, Guild, Officer), marks in the game world that point into it, and one launcher, the chip. Every surface the hub replaces is deleted in the lane that replaces it.

**Spec:** `design/specs/2026-11-13-addon-hub.md` is the authority. The Builds tab and the frame are `design/specs/2026-11-13-addon-builds-window.md`.

**Mocks:** `design/mocks/addon_hub.py` renders `design/reviews/2026-11-13-addon-hub/hub-*.png`. Every tab lane's review starts from a same-scale side by side of its in-game capture with its board.

**Gates for every lane that changes a visible surface:** ux-designer, wow-player, ai-slop-reviewer, info-density-reviewer and brand-consistency-reviewer SHIP/PASS on in-game captures (the Windows box or the owner's client); Guild and Officer also guild-officer-reviewer. Captures and verdicts go to `design/reviews/2026-11-13-addon-hub/<lane>/`.

## Order

```
L0 builds-window (in flight) ──> L1 hub frame ──┬─> L2 Me ────────┐
                                                ├─> L3 Gear ──────┤
                                                ├─> L4 Rotation ──┼─> L6 chip ─> L8 Panel and tour fold ─> L11 cleanup
                                                └─> L5 Guild ─> L7 Officer ┘
L9 data (parallel from the start) ─────────────────> L5 Coming, L7 readiness
L10 marks and Settings (parallel after L1)
```

L2, L3, L4 and L5 run in parallel once L1 lands. L6 needs the tabs it opens (L2 to L5). L8 needs every fold-in target to exist.

### How to add a tab (the API L1 landed; `surfaces/Hub.lua`'s header is the reference)

1. New file `surfaces/<Name>Tab.lua`, in the TOC after `surfaces\Hub.lua`. At the end of the file call `Hub.register { id = "<id>", label = L.hubTab<Name>, build, show, hide, escape, empty, figures, waiting }` with the id from `Hub.ORDER` (`me`, `gear`, `rotation`, `guild`, `officer`). Registering the id replaces the placeholder; order and the shared availability rule (`Hub.RULES`: Gear from level 10, Rotation with the class's rotation, Guild in a guild, Officer behind `Hub.officer()` or a master loot session) come from the id. An extra `available()` narrows it; never re-implement the shared rule.
2. `build(content)` runs once into the tab's own content frame. `show(options)` draws, calls `Hub.setHints(escape, right)` for the footer and `Hub.fitHeight(bodyHeight)`; the window keeps the tallest tab's height. `hide()` releases anything the tab holds; `escape()` returns true only when the tab stepped back itself; `empty()` returns a muted line in place of the body, or nil.
3. Never set the title or the crest: the hub titles every tab with the character's name over `Level N Class`. `figures()` returns at most two parts (`Hub.FIGURES_MAX`, extra parts are dropped) and optionally the lines for their hover.
4. `waiting()` returns `{ key, line, fact }` items: `line` is the chip's words, `fact` changes when the item is new again (defaults to the line). Any item draws the tab's dot; the open lands on the first unseen item (`Hub.landing`, priority `Hub.URGENT_ORDER`); opening the tab marks its items seen. Call `Hub.refresh()` when your figures or items change while the window is open.
5. Officer gates go through `Hub.officer()` (the player) and `Hub.officerRank(rankIndex)` (another member); no rank index checks anywhere else. `/fs <id>` already opens the tab or prints `Hub.reason(id)`; add no slash route.
6. Tests: a `tests/<name>_tab_spec.lua` that loads the tab with `helper.load` (add the module to `helper.HUB_TABS` so the hub reloads with it) and asserts on `Hub.headerFor`, `Hub.waitingOf` and the drawn body.
