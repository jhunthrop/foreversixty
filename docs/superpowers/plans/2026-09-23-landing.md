# Landing page redesign — plan

Lane: `landing` (worktree `.worktrees/landing`, branch `landing`, from `main`). Files: `web/**`
only.

## Global constraints (spec section 0/1, copied)

1. `design/DESIGN-SYSTEM.md` in full applies: Stone/Gold, Cinzel display (never above 22px on
   content pages), reference voice, sky band is the one page reveal, 44px targets.
2. Vocabulary: addon in game, companion on desktop, "from Battle.net" for Blizzard data.
3. States model: every island has a skeleton sized to ready state, a retry, an empty state,
   one `.reveal`.
4. Lighthouse strict bucket for `/`: performance 0.95, LCP 1800ms, TBT 100ms, CLS 0.05.
   Islands `client:visible` or later; LCP element is server-rendered text, never an island.
5. Honesty: every figure real, dated, sourced, or absent. No invented numbers.
6. `Header.astro`, `Footer.astro`, `components/ui/**`, `lib/ui/**` not touched.
7. Lane rules: sonnet only, never opus; commit rules; scoped checks; no broad `pkill`; stop
   servers before final report.

## Ruling log (recorded as work proceeds in `.superpowers/sdd/2026-09-23-landing/progress.md`)

Key upfront rulings (research phase, before implementation):

- Ruling 1: `GET /v1/rankings/guilds?kind=progress` exists and needs no `encounter` param
  (api/internal/rankings/handler.go, guilds.go) — used for the Rankings panel's top-5 guilds
  by bosses killed. Cost if wrong: panel always shows empty state; low.
- Ruling 2: the "Your guild" panel's progression figure comes from a second fetch
  (`fetchGuild`) once the member's guild is known, computing killed/total the same way
  `Guild.svelte` already does (`progression.filter(r => r.kills > 0).length` / `.length`).
  Cost if wrong: one extra client-side network call, never blocking LCP (client:visible).
- Ruling 3: no generic `/guilds` directory page exists. The signed-out/no-guild "Your guild"
  panel's link is the Battle.net sign-in URL (`battlenetStartUrl('/account?signed_in=1')`,
  same helper the hero button uses) — "claim your guild with a Battle.net sign-in" points at
  the sign-in itself. Cost if wrong: a lane note for the coordinator to redirect the link.
- Ruling 4: the standalone "Recent public reports" panel in the old "What changed" row is
  removed; `RecentReports` (`client:visible`, compact, heading=false) becomes the Logs
  product panel's live element instead — one real feed, not two copies of it on one page.
- Ruling 5: product panel CTA link text is "Open the planner" / "Open the simulator" /
  "Open the logs" / "Open the rankings" — unambiguous against the primary nav's plain
  "Planner"/"Simulator"/"Logs"/"Rankings" labels (nav.spec.ts already scopes to
  `primary-nav` for that reason).
- Ruling 6: reference tiles are `Classes` (`/classes`), `Guides` (`/guides`), `Zones`
  (`/zones`), `Dungeons` (`/dungeons`) — `tools.json`'s three `community` rows are renamed
  ("Zone atlas" → "Zones", "Class guides" → "Guides") and a fourth `Classes` row is added;
  `tools.json` has no other reader (checked).
- Ruling 7 (execution): given the single-session lane budget, task execution below is done
  directly (implement → scoped checks → self-review against the review checklist) rather
  than a literal fresh-subagent-per-task loop, since a fresh subagent would need this whole
  research context re-briefed at equal or greater cost. One independent sonnet review
  subagent runs over the finished diff before the final report, per the model budget note.
